# AMD format: nail it down before release

AMD's document layer (link-form headings, `---` fence, prose body, `- [label](target)`
choices) is sound. The **fence** grew per-domain across OU, LM and the a2x conversion and
is now four incompatible dialects with no declared vocabulary. Only `help_docs.amd` and
`library_docs.amd` have shipped, and **neither contains a single fence** - so the whole
data layer is free to redesign. This is that redesign.

Prime directive: **AMD is for sci-fi authors, not programmers.** Every naming choice below
is settled by reading it aloud and asking whether someone who has never programmed would
write it unprompted.

---

## 1. What the survey found

31 files, 280 fences, 114 distinct fence labels, 150 section keys, headings 4 deep
(94 / 94 / 212 / 32 by level). Plus 34 more `.amd` in `f:/a/a28_amd` generated by a2x.

| Finding | Evidence |
|---|---|
| Four fence readers, chosen by CALL SITE, not by the file | default `load_yaml_string` (quest.py:681); friendly `amd_parse_facts`; the brace-triggered whole-fence YAML flip; loaders that bypass both (`amd_recipe_data`) |
| Tooling and runtime read the same bytes differently | `recipes.amd`: runtime gets `Properties` as a nested dict, `amd_core` gets `properties: ''` + two colliding keys. `bar.amd`: runtime gets 5 chatter lines, `amd_core` gets `lines: ''` |
| The schema is a hand-written second copy that has drifted BOTH ways | 114 authored labels; `amd_schema` declares 47; only 31 overlap. 83 labels / 394 uses undeclared (incl. `pays` x50, `goal` x32); 16 declared fields never authored |
| Keys are a flat last-wins namespace | 374 keys, 40 duplicated. `peacetime_remastered.amd` alone: `recover` x3, `scan` x3, `florbin` x2 |
| ...and it produces a FALSE lint error today | `Then: reveal florbin/recover` is a correct path; `parent_of` is flat/last-wins so `path_resolves` says False. It is the only reference issue reported in the file and it is wrong |
| Heading LEVEL means nothing consistent | records sit at level 1 in 9 files, level 3 in 5, level 2 elsewhere - so `section_of()` / `archetype_for_section()` only work when records happen to land at level 3 |
| Malformed headings demote to prose silently | `#[X](k)`, `# [X](k`, indented headings. `_RE_SECTION` uses `match` not `fullmatch`, so `# [X](k) trailing` silently drops the trailing text; greedy `.*` makes `# [A](a) and [B](b)` parse as key `b` |
| Author words != player words | `State: idle` renders to the player as **"Available"** |
| `Goal:` does two jobs | it sets the completion trigger AND the objective text, so the quest log reads *"Signal 5 drone_down"* |
| Prose genuinely collides with field syntax | 12 of 279 record bodies open with a field-shaped line (`COMMS: hail the freighter.`, `SCIENCE: scan her.`) - which is why the `---` fence stays |

Baseline before any change: **1755 tests, 3 pre-existing failures** (all `test_a2x_props`,
unrelated to AMD).

## 2. The format, settled

### 2.1 The fence

```
---
Characters                   <- FIRST meaningful line, no colon: what these are
Color: #3399ff               <- a field
Home: 6, 4
Citation: a long line that   <- non-empty value: indented lines CONTINUE it
  wraps onto the next line
Properties:                  <- EMPTY value: indented lines NEST
  Monster: 'gui_drop_down(...)'
Lines:                       <- or become a list
  - "First bark."
  - "Second bark."
Modifiers: {speed: 2}        <- escape hatch: value starting { or [ is flow
// a comment
---
```

Rules:

- **The kind line** is the first meaningful line of the fence, a bare noun, no colon.
  Singular or plural both work (`Character` / `Characters`). Blank lines and `//`
  comments may precede it. It **inherits downward** - on a section it covers every
  record beneath; a record may override. Anywhere but the first line is an error that
  points at line 1. An unknown noun gets a guiding error, not a parse failure.
  `These are: characters` is accepted as the long form (what the docs and the Inspector
  show); it is the same declaration, not a second thing to learn.
- **One rule separates continuation from nesting:** an inline value means indented
  lines continue it (joined with a space); an empty value means they nest.
- Labels normalise (lowercase, `-`/space -> `_`). **Title Case is normative** for
  authoring.
- A line that is none of the above - no colon, not a list item, not a continuation -
  is an **error**. Today it is silently dropped.
- `{` / `[` at value-start is the permanently reserved escape hatch. Leading `!` is
  reserved for future directives. Everything else at value-start is literal text -
  which is what keeps `Color: #07F` (27 uses) and `Reveals: Survey logged: 3` (52
  colon-bearing values) working.

### 2.2 The `---` delimiter stays, but stops toggling

Considered and rejected: dropping it for "fields until the first non-field line" breaks
on the 12 real bodies that open `COMMS:` / `SCIENCE:`. Considered and held in reserve:
a blank-line separator (works on 100% of the corpus, but a blank line is invisible and
silently turns the rest of a record into prose).

New rules:

- `---` is meaningful only **immediately after a heading** (opens) or **while a block is
  open** (closes). Anywhere else it is prose.
- A heading always closes an open block.
- Unbalanced at EOF is an error. (Today it toggles, so one stray `---` inverts
  data-vs-body for the rest of the file. No file is unbalanced today - latent, not live.)

**Removed with it: "multiple data sections on one heading merge".** That was a
documented behaviour (`test_amd_parse_data_section_merges`) and it IS the toggle - a
second fence after prose could only work by letting any `---` in prose open a block.
Zero headings in the corpus (65 files, 1652 fences) carry more than one fence block,
so nothing authored relies on it.

### 2.3 Field descriptors are the single source of truth

One table entry owns alias + type + runtime key, replacing the eleven hand-maintained
`elif` chains AND the parallel `amd_schema` copy:

```python
field("pays",      type=reward(),   key="reward")
field("done when", type=trigger(),  key="on_signal", aka=("goal",))
field("state",     type=enum("available", "active", "secret", "complete", "failed"),
                   aka=("idle",))
```

The reader resolves alias -> coerces by declared type -> stores under `key`. Runtime,
linter, LSP, Inspector and formatter all read the one table, so drift becomes impossible
by construction rather than by comment.

Value grammars become named types, promoted from the private functions already in
`amd.py`: `duration()`, `pct()`, `weighted()`, `makeup()`, `coord2()`, `counted()`
(`salvage x5`), `kv()` (`kind=bio`), `trigger()`, `reward()`, `color()`, `face()`,
`csv()`, `ref()`, `signal()`.

### 2.4 Kind resolution order

1. the record's own kind line
2. the nearest ancestor that declares one (sections inherit down)
3. a document-level kind line (pre-heading fence)
4. the **section-name table**, which is extensible - a domain registers that sections
   named `jobs`, `contracts`, `bounties` hold quests
5. the existing `_DISCRIMINATORS` fallback

Step 4 is the common path. Most files never write a kind line at all.

### 2.5 Headings

- Index by **path**, not key. Bare-key lookup stays as a convenience that **errors on
  ambiguity** instead of silently taking the last.
- `resolve_target` / `path_resolves` walk real parent pointers (fixes the false lint
  error on `florbin/recover`).
- **Reference scope is relative**: self -> siblings -> ancestors -> global. This matches
  what authors already wrote and mirrors MAST's `---inline` label scoping.
- `fullmatch` + non-greedy groups; keys normalise like labels; duplicate-key lint.
- A line that starts with `#` outside a fence and outside a body but is not link-form is
  a lint warning (catches `#[X](k)`, missing paren, indented headings).

## 3. Vocabulary decisions

**Settled**

| Decision | Outcome |
|---|---|
| `Pays:` vs `Reward:` | keep **`Pays:`** - the corpus voted (50 uses); `aka` makes it reversible |
| `Goal:` doing two jobs | split: **`Objective:`** (the sentence players read) + **`Done when:`** (the trigger) |
| `When:` / `Goal:` / `Then:` | NOT redundant - three lifecycle slots. Rename for clarity: **`Starts when:`** (aka `when`), **`Done when:`** (aka `goal`), **`Then:`** |
| `State: idle` | rename to **`State: available`** - the word the player already sees. `idle` stays as `aka` |
| `signal` keyword | drop it - a bare token IS a signal (`Done when: 5 drone_down`); `reach 6, 4` keeps its verb because it is a different shape |
| kind line spelling | bare noun, first line, `These are:` as long form |
| Title Case labels | normative for authoring; normalised on read |

**Provisional (recommendations - overrule any of these and the plan absorbs it)**

| # | Decision | Recommendation |
|---|---|---|
| P1 | `?query` on headings | **Fold** into the field vocabulary so `?state=idle` validates exactly like `State:`. Only 12 uses (`state` x6, `icon_index` x6) |
| P2 | `Win:` overloaded as flag-or-prose | **Split** - `Win: true` stays a flag, end-screen text moves to `Win text:` |
| P3 | Reference scope | **Relative** (self -> siblings -> ancestors -> global) |
| P4 | Document-level config home | **The pre-heading fence.** It already parses (`amd_core` attaches it to the synthetic root) and it is the only option that works for the 9 flat files. `amd_doc.amd_root_data` currently means the level-1 title heading's fence - unify on the pre-heading one |
| P5 | Remaining jargon | rename `Scope:`, `Tier:`, `Archetype:` (OU clans) by the read-aloud test during the Phase 5 sweep |

## 4. Growth rules (post-release)

1. **Unknown fields warn, never fail, and are preserved.** An older sbslib must load a
   newer mission's `.amd`.
2. **Renames are free forever via `aka=`.** This is why none of the naming decisions
   above are high-stakes. There are TWO levels, and they are different mechanisms:
   - `field(..., aka=("goal",))` renames the **label** (`Goal:` -> `Done when:`)
   - `enum(..., aka={"idle": "available"})` renames a **value** (`State: idle` ->
     `State: available`). `enum_values` is what an author is OFFERED; `enum_accepts`
     is what the linter TOLERATES, so a retired spelling never gets flagged.

   **Renaming the authored name must not move the STORED key.** Pin `key=` to
   whatever the data was already stored under, so every existing reader keeps
   working. What a writer types and what the runtime stores are independent on
   purpose.
3. **Non-core vocabulary registers and collides loudly.** `amd_register_fields("universe",
   {...})` errors at registration on a clash with core - a startup failure, not silent
   drift. No `x-` sigil prefixes; ugly for a format writers read.
4. **`{` / `[` at value-start is the permanent escape hatch**, so no future shape needs a
   breaking syntax change. Leading `!` reserved for directives.
5. **No version field, deliberately.** Rules 1-2 cover additions and renames; the only
   gap is silently changing what an existing field MEANS, and the discipline there is:
   don't, add a new name.
6. **Error messages are addressed to a writer, not a compiler.** Every failure names the
   line, says what was expected in plain words, and guesses the intent:
   `line 12: expected "Label: value" - did you mean to put this in the body, below the ---?`
7. **Narrative core vs technical fringe.** Nesting appears in exactly 2 places across 31
   files, both tooling content; **no narrative file uses indentation at all**.
   Indentation-significance is YAML's worst trap for non-programmers and must stay at the
   fringe. If nesting starts appearing in dialogue or job files, the fringe has leaked.
8. **The read-aloud test gates every new field.** `Pays`, `Objective`, `Citation`,
   `Speaker`, `Scene` pass. `on_signal`, `archetype`, `idle`, `scope`, `tier` do not.

## 5. Worked example

Before (`peacetime_remastered.amd:73`, verbatim):

```
## [Jobs](jobs)

### [Gunnery Qualification](job_gunnery)
---
State: idle
On accept: toast Job accepted: Gunnery Qualification
On complete: toast Job complete: Gunnery Qualification
Goal: signal 5 drone_down
Pays: 200 credits
---
Weapons drill: destroy all the target drones.
```

After:

```
## [Jobs](jobs)

### [Gunnery Qualification](job_gunnery)
---
State: available
Objective: Destroy the target drones
Done when: 5 drone_down
Pays: 200 credits
---
Weapons drill: destroy all the target drones.
```

No kind line - the section is called `Jobs` and the name table resolves it. The two
`toast` lines are gone: "Job accepted: <name>" is the quest driver's default, authored
only when it differs. Five plain statements, no machine words.

## 7. Phases

Each phase ends green (1755 tests, only the 3 known `test_a2x_props` failures) and with
`sbs lint` clean across LM + OU + StormsBeacon + a28_amd.

| # | Phase | Touches |
|---|---|---|
| 1 | **Field-descriptor registry** - types, aliases, target keys; port one archetype, prove it, then the rest | sbs_utils |
| 2 | **One fence reader** - kind line, nesting, lists, continuation, per-value flow, non-toggling `---`, writer-facing errors | sbs_utils |
| 3 | **Kind resolution** - inherit -> extensible name table -> discriminators; `amd_core` and the runtime share one path | sbs_utils |
| 4 | **Headings** - path indexing, ambiguity errors, duplicate lint, `fullmatch`, key normalisation, unify the two "root"s | sbs_utils |
| 5 | **Vocabulary sweep** - all 114 labels declared; renames land with `aka`; read-aloud test applied | sbs_utils |
| 6 | **Mission migration** - delete the three bypass loaders; register OU vocabulary; verify LM/OU/StormsBeacon/demos | LM, OU, StormsBeacon |
| 7 | **a2x** - emitter moves to the new vocabulary; regenerate all 34 `a28_amd` files | arme2cosmos, a28_amd |
| 8 | **Linter + VS Code extension** - diagnostics, TextMate grammar, registry-driven Inspector | sbs_cli, editors/vscode |
| 9 | **Docs** | mkdocs |

Verification per phase: unit tests, then `sbs lint` over every `.amd` in the tree, then a
headless `--test` run of LM `peacetime_remastered` and OU, then the user's browser pass
where a GUI surface is involved.
